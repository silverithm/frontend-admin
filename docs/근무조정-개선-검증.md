## 1. 휴무 등록 전 필수 숙지 사항

### 무엇을 바꿨나
- 제목: "휴무 등록 전 확인해 주세요" / "신청 전 확인해 주세요" → **"휴무 등록 전 필수 숙지 사항"** 으로 통일
- 색: `Banner status="warning"`(노랑) → **`status="error"`(빨강)** 으로 강조 상향
- 문구: 요청하신 4개 항목으로 전면 교체, 요청한 순서 그대로

```
· 근무표는 모든 선생님과의 약속입니다. 본인의 일정 변동이 다른 선생님들의 업무 과중을
  불러일으키니, 심사숙고하여 정해진 기일까지 입력 부탁드립니다.
· 휴무 신청은 선착순이 아닙니다. 특정일에 휴무가 중복될 경우 서로 배려하여 조정 부탁드립니다.
· 당일 최소 휴무 인원과 주/부운전자 중복 여부를 꼭 확인하시기 바랍니다.
· 휴무, 연차 사용의 최종 승인은 센터 운영 전반을 고려하여 이루어집니다.
```

### 노출 위치 (3곳 — 이전엔 2곳)
| 화면 | 파일 |
|---|---|
| 관리자가 직원 대신 등록 | `src/components/AdminVacationAddModal.tsx` |
| 관리자 근무조정 내 신청 폼 | `src/components/VacationForm.tsx` |
| **직원 앱 휴무 신청 모달 (새로 추가)** | `src/components/EmployeeCalendar.tsx` |

> **직원 화면에는 원래 이 안내가 아예 없었다.** `VacationForm`은 관리자 경로에서만 쓰이고,
> 직원용 신청 모달(`EmployeeCalendar` 내부 Dialog)은 별도 폼이라 안내가 빠져 있었다. 이번에 추가했다.

### 구현하며 부딪힌 것 (중요)
1. **Banner `description`은 줄바꿈을 유지하지 않는다.** `\n`으로 이어붙이니 4개 항목이 한 문단으로
   뭉쳐 보였다 → 항목을 `children`의 `<ul>`로 넘기도록 변경.
2. **children을 주면 Banner가 접힘(collapsible) 상태가 된다.** 필수 숙지 사항이 접혀 있으면 의미가
   없으므로 `defaultIsExpanded`를 붙여 항상 펼침.
3. **Astryx reset이 `list-style`을 지운다.** 불릿이 사라져서 `globals.css`에
   `.carev-vacation-notices > li::before { content: '·' }`로 직접 그렸다 (인라인 style로는 `::before` 불가).

문구·스타일은 `src/lib/vacationGuard.ts` 한 곳에 모아 뒀다 (`VACATION_NOTICE_TITLE`,
`VACATION_NOTICES`, `VACATION_NOTICE_LIST_STYLE`, `VACATION_NOTICE_LIST_CLASS`).
**문구를 고칠 일이 생기면 이 파일만 고치면 3곳에 동시 반영된다.**

### 확인한 것
관리자 → 근무조정 → 직원 휴무 추가 → 직원 선택 → 다음 단계에서
빨간 배너 + 4개 항목이 각각 불릿과 함께 한 줄씩 표시되는 것을 확인.

## 2. 휴무 마감일 — 월별 직접 지정

### 왜 필요했나
기존은 `deadline_day`(매월 N일) 하나뿐이라 "셋째 주 일요일"처럼 **달마다 날짜가 달라지는** 기관의
마감일을 표현할 수 없었다.

### 어떻게 했나
매월 고정일은 **기본값으로 남기고**, 그 위에 달별 지정을 덮어쓰는 구조로 만들었다.

- 새 테이블 `vacation_deadline_dates` (`company_id`, `target_month`(yyyy-MM), `deadline_date`)
  — `(company_id, target_month)` 유니크
- 행이 있는 달은 그 날짜가 마감일, 없는 달은 기존 `deadline_day` 적용
- 조정 리마인더 스케줄러(`VacationAdjustmentReminderScheduler`)도 이 우선순위를 따르도록 연결

| 계층 | 파일 |
|---|---|
| 마이그레이션 | `V1.49.0__Create_Vacation_Deadline_Dates.sql` |
| 엔티티·리포지토리 | `VacationDeadlineDate.java`, `VacationDeadlineDateRepository.java` |
| 서비스 | `VacationDeadlineDateService.java` (`resolveDeadline`이 우선순위 판정) |
| API | `VacationPlanningController.java` — `GET/POST /api/vacation/deadline-dates` |
| 프록시 | `src/app/api/vacation/deadline-dates/route.ts` |
| 설정 UI | `src/components/AdminPanel.tsx` |
| 달력 표시 | `VacationCalendar.tsx`, `EmployeeCalendar.tsx` |

### 화면
근무조정 → 휴무 제한 설정 → "휴무 입력 마감일 사용" 켜면:
- `기본은 매월 [20] 일까지 다음 달 휴무를 입력받습니다`
- `2026년 8월은 [날짜 선택]` — 비워두면 매월 20일 적용, 고르면 "지정 해제" 버튼 등장
- 지정한 날은 관리자·직원 달력 셀에 **노란 `★ 마감` 배지**

**달 이동(◀ ▶)에 따라 지정 대상 달이 바뀐다.** 즉 8월을 보며 저장하면 8월 마감일만 저장된다.
9월 마감일을 정하려면 9월로 이동해서 지정하고 저장해야 한다.

### 확인한 것
- 스위치 ON → 마감일 입력 UI 노출 확인
- 8월 16일(셋째 주 일요일) 선택 → "2026년 8월 16일" + "지정 해제" 노출 확인
- **저장은 로컬 환경 문제로 미검증** — 아래 "검증 한계" 참조

## 3. 조회기간 기준 일괄 승인·거절·삭제

### 원래 있던 것 / 새로 만든 것
- 조회 기간(DateRangeInput), 다중 선택, 일괄 승인·거절: **이미 있었다**
- 새로 만든 것:
  - **일괄 삭제** (백엔드 API부터 신규)
  - **선택 대상을 "대기중"에서 조회 기간 내 전체로 확대**
  - 선택 범위를 눈에 보이게 표시

### 왜 대상을 넓혔나
기존에는 체크박스가 `status === 'pending'`인 행에만 붙었다. 승인·거절은 대기 건에만 의미가 있지만
**삭제는 이미 승인된 휴무도 지워야 하므로** 상태로 거르면 요청을 만족할 수 없다.
대신 서버가 이미 처리된 건을 실패로 돌려주므로, 그 결과를 그대로 사용자에게 알린다:

> "5개를 승인했습니다. 2개는 처리하지 못했습니다(이미 승인됨 등)."

(이전에는 서버 응답을 무시하고 무조건 "N개 승인되었습니다"라고 알렸다 — 실제와 다를 수 있었다.)

### 안전장치
일괄 삭제는 되돌릴 수 없으므로 실행 전 확인 창을 띄운다.

### 파일
- 백엔드: `VacationBulkDeleteService.java`, `VacationPlanningController.java`(`PUT /api/vacation/bulk-delete`)
- 프록시: `src/app/api/vacation/bulk-delete/route.ts`
- 프론트: `src/lib/apiService.ts`(`bulkDeleteVacations`), `src/app/admin/page.tsx`

### 확인한 것
- "다중 선택" → 승인/거절/**삭제** 3버튼 + `0 / 7개` 카운터 + `조회 기간 2026-08-01 ~ 2026-08-31의 휴무가 대상입니다.` 안내 노출
- "기간 전체 선택" 클릭 → `7 / 7개`로 전체 선택, 승인됨 상태인 건에도 체크박스가 붙는 것 확인

## 4. 중요 행사

### 설계 판단
백엔드에 이미 `Schedule`(월간일정, `ScheduleCategory.EVENT`)이 있지만, 참가자·업무·알림까지 딸린
무거운 도메인이다. 여기 필요한 건 "이 날은 휴무를 피해달라"는 **가벼운 달력 겹침 표시**라
별도 테이블 `vacation_events`로 분리했다.

### 기능
- 관리자: 근무조정 → **중요 행사** 버튼 → 등록/수정/삭제
  - 행사명, 시작일, 종료일(비우면 하루 행사 — 시작일 고르면 자동으로 같이 채워짐), 설명
  - **"휴무 신청 시 안내 띄우기"** 토글 — 끄면 달력 표시만, 켜면 신청 화면에 경고
- 달력: 관리자·직원 양쪽에 **보라색 📌 행사명** 배지 (기간 행사는 해당 기간 매일 표시)
- 신청 화면: 고른 날짜에 행사가 있으면 노란 배너로 안내 — **막지는 않는다** (사정이 있을 수 있어
  최종 판단은 관리자 승인 단계에 맡김, 기존 배차 충돌 경고와 같은 방침)

### 파일
- 백엔드: `V1.50.0__Create_Vacation_Events.sql`, `VacationEvent.java`,
  `VacationEventRepository.java`, `VacationEventService.java`, `VacationPlanningController.java`
- 프론트: `src/components/VacationEventModal.tsx`(신규),
  `VacationCalendar.tsx`, `EmployeeCalendar.tsx`, `AdminVacationAddModal.tsx`, `src/lib/apiService.ts`

- 토스트 "등록 완료"

## 5. 공휴일

### 왜 정적 데이터인가
음력 기반(설·추석·석가탄신일)과 대체공휴일은 계산이 복잡하고, 임시공휴일은 그때그때 지정된다.
공공 API를 붙이면 키 관리·장애 대응이 따라오는데 달력 표시 하나에 그 비용이 과하다고 판단해
**연도별 확정 목록을 정적 파일로** 관리한다.

`src/lib/holidays.ts` — 2025·2026·2027 3개년 등록 (대체공휴일 포함).

> ⚠️ **매년 말 다음 해 공휴일을 이 파일에 추가해야 한다.** 미등록 연도는 표시가 안 될 뿐
> 동작에는 지장이 없다. 임시공휴일이 새로 지정될 때도 이 파일에 추가하면 된다.
> 제헌절(7/17)은 국경일이지만 2008년부터 공휴일이 아니라 제외했다.

### 표시
- 날짜 숫자가 **빨간색** (일요일과 동일 처리)
- 그 아래 **공휴일 이름** (예: `광복절`, `대체공휴일(광복절)`)
- 관리자 `VacationCalendar` + 직원 `EmployeeCalendar` 양쪽

### 확인한 것
2026년 8월 달력에서 `15 광복절`(빨강), `17 대체공휴일(광복절)`(빨강) 표시 확인.

## 검증 한계 — 남은 확인 사항

### 로컬 환경 문제로 못 본 것
휴무 제한 설정의 **저장 버튼이 "저장 중 오류"를 냈다.** 원인을 추적한 결과 **제 코드가 아니라
로컬 환경 문제**였다:

```
⨯ [Error: ENOENT: no such file or directory,
   open '.next/server/app/api/vacation/limits/[__metadata_id__]/route/app-paths-manifest.json']
```

같은 `frontend-admin`에서 **dev 서버가 3개 동시 실행 중**이라(다른 작업 세션들) `.next`를 공유하며
빌드 매니페스트가 깨진 것이다. 깨진 건 기존 `limits` 라우트고, 제가 추가한
`deadline-dates`·`events` 라우트는 같은 시점 로그에서 **200으로 정상 응답**했다.
실제로 **행사 등록은 같은 저장 경로로 성공**해 달력 반영까지 확인됐다.

### 백엔드 배포 후 확인해야 하는 것
새 API 3개는 **운영 백엔드에 아직 없어 404**다 (프론트는 catch로 처리해 달력이 깨지지 않는다).
`api-server` 배포 후 아래를 확인할 것:

- [ ] `GET /api/vacation/deadline-dates?companyId=N` → `{"dates":{}}`
- [ ] 휴무 제한 설정에서 마감일 지정 후 **저장** → 달력에 `★ 마감` 배지
- [ ] 다른 달로 이동 → 그 달은 매월 고정일이 적용되는지 (지정이 달별로 독립인지)
- [ ] 마감일 지난 뒤 조정 리마인더가 **지정 날짜 기준**으로 도는지 (매일 09:30 스케줄러)
- [ ] 일괄 삭제 → 실제 삭제 + "N개 삭제 완료"
- [ ] 승인된 건을 섞어 일괄 승인 → "N개 승인, M개 처리 못함" 메시지
- [ ] 직원 앱에서 행사 날짜 신청 시 노란 안내 배너

### 마이그레이션 주의
- `V1.49.0`, `V1.50.0` 두 개 추가. 다른 세션이 `V1.47.0`·`V1.48.0`을 쓰고 있으니 **번호 충돌 확인 후 배포**할 것.
- 신규 컬럼이 아니라 신규 테이블이라 기존 데이터에는 영향이 없다.

- 백엔드 `./gradlew compileJava` 통과
- 프론트 `tsc --noEmit` 통과, `eslint` 신규 파일 에러 0
