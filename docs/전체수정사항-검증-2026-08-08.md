## 2. 접속 상태(presence) 검증 상세

브라우저 대신 STOMP 클라이언트로 직접 붙여 서버 등록 여부를 확인했다.

```
접속 전:      {"onlineUserIds":[]}
수신 프레임:  CONNECTED
수신 프레임:  MESSAGE          ← /topic/presence/95 브로드캐스트 도착
접속 후:      {"onlineUserIds":["94"]}
WS 종료:      1000
연결 종료 후: {"onlineUserIds":[]}
```

세 가지가 한 번에 확인된다.
- `/app/presence/join`이 서버에 도달해 접속자로 등록된다
- 같은 기관 구독자에게 상태 변화가 즉시 방송된다
- 연결이 끊기면 `SessionDisconnectEvent`로 자동 오프라인 처리된다

## 3. 이번 회차에 발견해서 고친 결함

### 홈페이지 목록 조회가 항상 404 (실제 사용자 영향 있음)

증상: 사이드바 `우리 기관` 링크가 하나도 뜨지 않고, 기관 프로필 화면을 다시 열면 저장해둔 주소가 비어 보였다.

원인: 저장용 프록시(`/api/v1/users/company-homepage-links`)만 만들고, 조회용 경로(`/api/v1/users/company-homepage`)에 대응하는 Next 라우트를 만들지 않았다. 백엔드에는 두 경로가 모두 있는데 프런트 프록시가 없어 Next가 HTML 404를 돌려주고 있었다.

```
GET /api/v1/users/company-homepage 404 in 186ms
[API Error] 서버에서 HTML 페이지를 반환했습니다. API 엔드포인트를 확인해주세요. (404)
```

조치: `src/app/api/v1/users/company-homepage/route.ts`에 GET·PUT 프록시 추가. 조회가 2건의 링크와 대표 주소를 정상 반환하는 것까지 확인했다.

## 4. 특이사항 — 다음 사람이 헛짚지 않도록

1. **개발 서버를 3000번이 아닌 포트로 띄우면 채팅이 안 붙는다.**
   백엔드 CORS 허용 목록이 `http://localhost:3000`, `carev.kr`, `www.carev.kr`, 넷리파이 주소로 한정돼 있다. 3999번으로 띄웠더니 SockJS 핸드셰이크(`/ws/chat/info`)가 nginx 로그 기준 **403**으로 막혔고, 브라우저에는 503으로 보였다. 결과적으로 WebSocket이 아예 연결되지 않아 접속 상태가 빈 배열로 나왔다. 코드 결함이 아니라 포트 문제였다.
   → 채팅·접속 상태를 로컬에서 확인할 때는 반드시 **3000번**을 쓸 것.

2. **채팅 공지는 자유 문구가 아니라 "메시지 고정" 방식이다.**
   `PUT /chat/rooms/{id}/notice`는 `{ messageId, setByName }`을 받는다. `content`를 보내면 서버가 해제 요청으로 해석해 `"공지를 내렸습니다."`를 반환한다(공지가 지워짐). 카카오톡 공지와 같은 동작이다.

3. **자료실 등록은 `filePath` 기반이다.**
   `{ title, fileName, fileSize, filePath, uploaderId, uploaderName }`이 필수. `fileUrl`로 보내면 `"제목과 파일은 필수입니다."` 400이 난다.

4. **채팅 파일은 전용 업로드 엔드포인트를 써야 한다.**
   일반 업로드 API는 상대 경로를 돌려줘 `<img src>`가 깨진다. `POST /chat/rooms/{id}/files`는 S3 절대 URL을 돌려주므로 웹·앱이 같은 값을 그대로 쓴다.

5. **데모 토큰 수명은 30분이다.**
   만료된 토큰으로 조회하면 `{"error":"Token expired"}`가 오는데, 파싱 코드가 이를 빈 배열로 삼켜 "결과 없음"처럼 보인다. 검색·파일함이 비어 보이면 토큰부터 갱신(`POST /api/v1/refresh-token`)할 것.

6. **접속 상태는 메모리에 둔다(의도된 선택).**
   서버가 재시작하면 전원 오프라인으로 초기화되는데, 이게 맞는 동작이다. DB에 두면 비정상 종료 때 유령 접속자가 남는다. 다중 탭·다중 기기는 세션 수를 세어 마지막 연결이 끊길 때만 오프라인 처리한다.
